# 本地校验只拦"文档白纸黑字且失败代价高"的错误

CLI 在发请求前做多少参数校验，存在两个极端：完整镜像官方文档的所有约束（会随文档更新持续漂移，CLI 本身变成 bug 源），或完全透传交给服务端（Seedance 2.5 auto 模式下参数错误是异步报错——任务创建成功、轮询到 failed 才见到错误，用户白等且可能已计费）。我们选择中间态：**只有同时满足"文档明确写死、且失败要么异步暴露要么浪费明显时间/费用"的规则才做本地拦截**（按模型的 Capability 查表：分辨率档位、时长范围、素材数量上限、代际专属参数、2.5 强制 adaptive 的场景），其余一律透传，让服务端做权威裁决。

两条硬边界：CLI **永不探测媒体文件内容**（不校验视频/音频时长、图片像素/宽高比——那需要引入 ffprobe 类依赖，且这类失败是同步报错，代价低）；**文档自相矛盾之处不做本地校验**（如 2.5 输入视频分辨率在两处文档说法不一）。

后果：部分非法请求会按设计到达服务端；Capability 表中每条规则都应可溯源到文档条目，文档更新时同步修表。
